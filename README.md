## Описание проекта

Проект представляет собой веб-систему для автоматической обработки аудиофайлов. Пользователь загружает аудио через браузер, после чего система выполняет подготовку звука, выделение речевых участков, диаризацию говорящих и автоматическую транскрибацию речи.

Система разработана в рамках курсовой работы по теме «Разработка системы автоматической транскрибации и диаризации речи на основе нейронных сетей».

## Основные возможности

- загрузка аудиофайла через веб-интерфейс;
- поддержка форматов `.mp3`, `.wav`, `.m4a`, `.flac`, `.ogg`;
- преобразование аудио в WAV mono 16 kHz;
- предварительная обработка звука через FFmpeg;
- выделение речевых фрагментов с помощью Silero VAD;
- автоматическая транскрибация речи с помощью faster-whisper;
- диаризация речи с использованием NVIDIA NeMo / TitaNet;
- формирование результата с временными метками и обозначениями говорящих;
- скачивание результата в формате `.txt`;
- удаление временных файлов после обработки или по запросу пользователя.

## Требования

Для запуска проекта требуется:

- установленный Docker;
- установленный NVIDIA Container Toolkit;
- видеокарта NVIDIA с поддержкой CUDA;
- доступ к интернету при первой сборке Docker-образа и загрузке моделей.

Проект рассчитан на запуск в Docker-контейнере с доступом к GPU. В текущей версии диаризация выполняется только через GPU. Если CUDA недоступна, обработка завершится ошибкой.

Отдельно устанавливать Python-библиотеки на основной компьютер не нужно: зависимости устанавливаются внутри Docker-образа из файла `Dockerfile`.

## Как запустить проект

### 1. Клонировать репозиторий

```bash
git clone https://github.com/username/speech_web_v3.git
cd speech_web_v3
```

Если проект уже скачан архивом, достаточно открыть терминал в папке `speech_web_v3`.

### 2. Собрать и запустить контейнер

```bash
docker compose up --build
```

После запуска открыть веб-интерфейс в браузере:

```text
http://localhost:5000
```

Если контейнер уже был собран ранее, можно запускать без пересборки:

```bash
docker compose up
```

Остановить контейнер можно командой:

```bash
docker compose down
```

## Проверка GPU внутри контейнера

Для проверки доступности видеокарты выполните:

```bash
docker compose run --rm speech-core python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA not available')"
```

Если всё настроено правильно, команда должна вывести `True` и название видеокарты.

Дополнительно можно проверить доступ Docker к видеокарте:

```bash
docker run --rm --gpus all nvidia/cuda:12.0.0-base-ubuntu22.04 nvidia-smi
```

## Работа с веб-интерфейсом

1. Открыть страницу `http://localhost:5000`.
2. Выбрать аудиофайл.
3. Выбрать режим улучшения аудио:
   - `Без улучшения` — только преобразование в WAV mono 16 kHz;
   - `Среднее улучшение` — фильтрация низких и высоких частот, шумоподавление, нормализация динамики;
   - `Сильное улучшение` — более выраженная фильтрация и шумоподавление.
4. Запустить обработку.
5. Дождаться завершения этапов обработки.
6. Скачать результат в формате `.txt`.

Пример результата:

```text
[0.00 - 3.42] SPEAKER_00: текст первого говорящего
[3.50 - 8.10] SPEAKER_01: текст второго говорящего
```

## Этапы обработки аудио

1. Пользователь загружает аудиофайл.
2. Flask-приложение сохраняет файл во временную папку `uploads/`.
3. Выполняется предварительная обработка аудио через FFmpeg.
4. Файл приводится к формату WAV mono 16 kHz.
5. Silero VAD выделяет речевые участки.
6. NVIDIA NeMo / TitaNet формирует эмбеддинги голосов.
7. Агломеративная кластеризация определяет условных говорящих.
8. faster-whisper распознаёт речь на выделенных фрагментах.
9. Текст сопоставляется с говорящими.
10. Соседние фрагменты одного говорящего объединяются.
11. Формируется итоговый `.txt` файл.
12. Временные файлы удаляются.

## API

Веб-приложение использует внутренние API-маршруты.

### `POST /api/upload`

Загрузка файла и запуск обработки.

Параметры формы:

- `file` — аудиофайл;
- `enhance_mode` — режим улучшения аудио: `none`, `medium`, `strong`.

Пример ответа:

```json
{
  "job_id": "идентификатор_задачи"
}
```

### `GET /api/status/<job_id>`

Получение статуса обработки.

Пример ответа:

```json
{
  "status": "processing",
  "stage": "ASR: распознавание речи",
  "progress": 80,
  "eta_sec": 20,
  "result": null,
  "error": null
}
```

### `GET /api/download/<job_id>`

Скачивание результата обработки в формате `.txt`. После скачивания исходный загруженный файл удаляется, а задача убирается из памяти приложения.

### `POST /api/delete/<job_id>`

Удаление загруженного файла и данных задачи без скачивания результата.

## Описание основных файлов

### `app/web.py`

Содержит Flask-приложение, маршруты загрузки файла, проверки статуса, скачивания результата и удаления задачи. Для каждой обработки создаётся отдельная задача с уникальным `job_id`. Обработка запускается в отдельном потоке, чтобы веб-интерфейс мог показывать прогресс.

### `app/pipeline.py`

Главный модуль обработки аудио. В нём последовательно выполняются улучшение звука, конвертация, VAD, диаризация, транскрибация, объединение результатов и формирование итогового текста.

### `app/audio_enhance.py`

Модуль предварительной обработки аудио. Использует FFmpeg-фильтры `highpass`, `lowpass`, `afftdn` и `dynaudnorm`. В проекте предусмотрены три режима обработки: `none`, `medium`, `strong`.

### `app/diarization_gpu.py`

Модуль диаризации речи. Использует модель `titanet_large` из NVIDIA NeMo для получения эмбеддингов голосов. Затем эмбеддинги кластеризуются с помощью агломеративной кластеризации, после чего близкие сегменты одного говорящего объединяются.

### `app/utils/cleanup.py`

Вспомогательный модуль для безопасного удаления файлов и временных папок.

## Очистка временных файлов

Система не рассчитана на постоянное хранение пользовательских аудиофайлов. Временные файлы удаляются:

- после скачивания результата;
- после ручного удаления задачи;
- после завершения внутренних этапов обработки временных WAV-файлов.

Перед отправкой проекта желательно удалить временные папки и служебные файлы, если они появились после запуска:

```bash
rm -rf uploads tmp __pycache__ app/__pycache__ app/utils/__pycache__
```

На Windows это можно сделать вручную через проводник.

## Возможные ошибки

### CUDA недоступна

Ошибка возникает, если контейнер не видит видеокарту. Нужно проверить установку NVIDIA Container Toolkit и доступность GPU внутри контейнера.

### Порт 5000 уже занят

Если порт занят другим приложением, можно изменить порт в `docker-compose.yml`:

```yaml
ports:
  - "5001:5000"
```

После этого веб-интерфейс будет доступен по адресу:

```text
http://localhost:5001
```

### Первая обработка выполняется долго

При первом запуске могут загружаться модели и инициализироваться библиотеки. Последующие обработки обычно запускаются быстрее, так как модели кэшируются в памяти приложения.

## Ограничения

Текущая версия проекта является учебной и демонстрационной. Она показывает общий подход к построению системы транскрибации и диаризации речи, но не является промышленной системой.

Для практического применения требуется дополнительная обработка ошибок, авторизация пользователей, ограничение размера загружаемых файлов, журналирование и более строгая политика хранения данных.
